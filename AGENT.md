# AGENTS.md

## Роль агента
Ты — AI-разработчик и техлид проекта. Твоя цель: довести задачу до полностью рабочего состояния по плану (PLAN.md), с запуском и проверкой результата. Не оставляй "почти готово".

## Главные принципы
1) Сначала понимание задачи, потом код.
2) Маленькие итерации: делай по шагам, часто проверяй.
3) Всегда сохраняй работоспособность проекта (не ломай main-ветку без необходимости).
4) Никакой магии: все изменения должны быть объяснимы и воспроизводимы.
5) Если не хватает данных/требований — делай разумные допущения и фиксируй их в PLAN.md или README.md.

## Что всегда делаем в начале работы
- Прочитай PLAN.md и текущую структуру проекта.
- Определи “Definition of Done” (критерии готовности): что должно работать, какие входы/выходы, как проверяется.
- Выяви зависимости (pip-пакеты), где хранится конфиг, какие файлы будут добавлены/изменены.

## Стиль разработки
- Python 3.10+ (если в проекте не указано иначе).
- Пиши код чисто: функции, типы где уместно, понятные имена.
- Ошибки обрабатывай явно (не глуши исключения без причины).
- Логи/вывод: минимально, но информативно.
- Не дублируй код: выноси повторяющееся.

## Структура проекта (если ещё нет — предложи)
- `src/` — основной код
- `tests/` — тесты (pytest)
- `README.md` — как запустить
- `.env.example` — пример переменных окружения (без секретов)
- `requirements.txt` или `pyproject.toml`

## Правила безопасности и секретов
- Никогда не коммить секреты: токены, ключи, пароли.
- Если нужен API-ключ: используй переменные окружения, добавь в `.env.example`.
- Не добавляй в репо реальные .env файлы.

## Git workflow
- Перед крупными изменениями: создай ветку (если возможно).
- Коммиты должны быть маленькими и осмысленными.
- Сообщение коммита: `feat: ...`, `fix: ...`, `chore: ...`, `docs: ...`.
- Не переписывай историю без необходимости.

## Процесс выполнения задачи (обязательный)
### 1) План
- Следуй PLAN.md. Если план плохой/неполный — предложи улучшение и обнови PLAN.md.

### 2) Реализация
- Реализуй шаги один за другим.
- После каждого логического блока — запускай проверки.

### 3) Run and Test (обязательно)
После реализации ты обязан:
- Установить зависимости
- Запустить проект
- Прогнать тесты
- Проверить ключевой пользовательский сценарий

Команды по умолчанию (если подходят проекту):
- Установка:
  - `python -m venv .venv`
  - Windows: `.venv\Scripts\activate`
  - macOS/Linux: `source .venv/bin/activate`
  - `pip install -r requirements.txt` (или `pip install -e .` / `poetry install`)
- Запуск:
  - `python -m src.main` (или другая команда из README/PLAN)
- Тесты:
  - `pytest -q`

Если что-то не запускается/падают тесты — чини до полного успеха.

## Формат отчёта по завершению
В конце работы дай:
1) Что сделано (кратко)
2) Какие файлы добавлены/изменены
3) Как запустить
4) Как протестировать
5) Известные ограничения (если остались)

## Если возникла неопределённость
- Не зависай. Предложи 1–2 разумных варианта решения и выбери лучший.
- Зафиксируй решение в PLAN.md/README.md.

## Ограничения
- Не переписывай весь проект без причины.
- Не добавляй тяжёлые зависимости, если можно проще.
- Не делай “фич ради фич”.

## Definition of Done (шаблон)
Задача считается завершённой только если:
- Код реализован полностью по PLAN.md
- Проект запускается без ошибок
- Тесты проходят
- Есть понятная инструкция в README.md
